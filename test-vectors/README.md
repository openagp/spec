# Cross-language test vectors — v0.1

This directory holds **deterministic byte-level test vectors** that every AGP implementation MUST pass. They are the contract that makes signatures interoperate across languages.

## Files

| File | Purpose |
|---|---|
| [`v0.1-canonicalization.json`](v0.1-canonicalization.json) | RFC 8785 JCS vectors. For each input, implementations MUST produce identical canonical UTF-8 bytes (verified by hex match and by SHA-256 hash). |
| [`v0.1-signatures.json`](v0.1-signatures.json) | Sign + verify vectors with a fixed test keypair. For each input, implementations MUST produce identical signing-input bytes and identical Ed25519 signatures (Ed25519 is deterministic per RFC 8032). |

## How implementations consume these

The Python and TypeScript reference SDKs each have an `interop` test that:

1. Loads `v0.1-canonicalization.json`. For each vector, runs the implementation's `canonicalize()` on `input` and asserts the resulting hex matches `expected_canonical_utf8_hex`.
2. Loads `v0.1-signatures.json`. For each vector, runs the implementation's signing protocol (per [ADR 0001](../decisions/0001-signature-canonicalization.md)) with `test_keypair.private_key_b64` and `key_id` and asserts the produced signature matches `expected_signature_b64`. Then `verify()`s using `test_keypair.public_key_b64`.

If either assertion fails, the implementation is **not interop-compliant** with v0.1, regardless of how many of its own tests pass. This is the test that catches subtle JCS bugs (Unicode normalization, number formatting, key ordering with non-ASCII keys) before they ship.

## How to regenerate

These vectors are generated by the Python reference SDK. To regenerate (only when the canonicalization or signing protocol changes per a new ADR):

```bash
cd ../sdk-python
.venv/bin/python -c "
# inline script that imports from openagp and writes both JSON files
# (see commit history for the original generator)
"
```

The Python implementation is the canonical source — if a future change to RFC 8785 or to the AGP signing protocol invalidates these vectors, the Python SDK is updated first, vectors are regenerated, then other implementations re-test.

## Test key warning

The keypair embedded in `v0.1-signatures.json` is a **fixed, public, hardcoded test key** with a deterministic seed ("OPENAGP_TEST_KEY_FOR_INTEROP_VEC"). It is intended for cross-language interop testing only.

**Never use this key for any real AGP traffic.** Anyone reading this repo can sign and verify with it. Any AGP receiver that accepts a signature from `key_id: openagp-interop-test-key` outside of test contexts is mis-implemented.
